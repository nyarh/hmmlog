# C++ Core Guidelines 연재 운영

사용자가 승인한 범위는 공식 문서 전체를 쉽게 설명하는 본편 120편과 참고글 3개다. 2026년 11월 19일 첫 집필 범위로 시리즈 안내와 1부 1~4편을 완성하고 이후 순차 집필하기로 정했다.

## 현재 진행

- 시리즈 안내: `src/content/posts/cpp-core-guidelines.md`
- 현재 집필 묶음: 2부 5~19편 변수와 표현식부터 안전하게
- 상태: 시리즈 안내와 1~19편 작성 및 검증 완료
- 다음 회차: 3부 20편 함수 하나가 맡을 일과 이름 정하기
- 사이트 배포: 프로젝트 루트 `AGENTS.md`의 Cloudflare Pages 절차를 따른다.

## 계획 파일

- `outline.csv`: 120편과 참고글 3개의 제목, 규칙 배정, 집필 메모, 현재 상태와 경로
- `rule-coverage.csv`: 번호가 있는 원문 항목별 주담당 회차와 원문 상태
- `section-coverage.csv`: 소개·보조 장·부록을 포함한 장과 절의 담당 회차
- `plan-metadata.json`: 원문 식별 정보, 검토 범위, 편집 원칙과 현재 집필 단계
- `validation.json`: 1부 발행 당시의 검증 결과와 게시 파일 해시
- `validation-part2.json`: 2부 예제 검증과 최신 목차·탐색 링크를 포함한 게시 파일 해시

512개라는 검토 항목 수에는 FAQ, 프로필, 초안과 삭제 항목이 포함된다. 이를 공식 문서의 유효한 규칙 개수로 소개하지 않는다. `T.142?`는 찾아보기에서 `T.142`로 정규화했고, 본문이 없는 `T.30`과 `T.31`은 초안 상태로 기록했다.

독자에게 제공하는 규칙 색인은 `public/attachments/cpp-core-guidelines/rule-index.csv`에 둔다. 운영 메모를 제외한 회차·작성 상태·글 주소·원문 주소만 제공한다. 글을 추가하면 목차와 색인을 함께 갱신한다.

## 다음 글을 쓸 때

1. `src/content/AGENTS.md`와 해당 회차의 집필 메모를 읽는다.
2. `rule-coverage.csv`의 원문 링크에서 배정된 규칙의 이유·예외·검사 방법까지 확인한다. 원문 변경이 있으면 식별 정보와 배정표를 갱신한다.
3. 필요한 선행 개념과 설명할 질문을 정한다. 전후 글을 읽지 않아도 핵심 상황은 이해할 수 있게 도입에서 짚는다.
4. 한 가지 문제를 중심으로 직접 작성한 짧은 예제를 사용한다. 완전한 실행 코드, 일부만 보여주는 코드, 의도적으로 컴파일에 실패하는 코드를 구분한다.
5. 실행 예제를 실제 컴파일하고 정상·경계·실패 입력을 확인한다. 컴파일러와 옵션, 필요한 표준 버전을 본문에 적는다. 성능 주장은 별도 측정이 있을 때만 사용한다.
6. 기존 `source-card` 형식으로 공식 문서 링크를 넣는다. 카테고리는 `개발/C++/Core Guidelines`, 표지는 `code`를 사용한다.
7. 시리즈 안내, 이전·다음 글 링크, 독자용 규칙 색인, 계획의 진행 상태를 함께 갱신한다. 미작성 회차에는 존재하지 않는 URL을 만들지 않는다.
8. `pnpm build`와 변경 검사, 내부 링크·첨부 파일 확인을 마친 뒤 검증 결과를 기록한다.

## 1부 예제 검증

1편은 실행 코드 없이 문서의 목적과 읽는 방법을 설명한다. 2~4편은 Markdown의 완전한 C++ 코드 블록을 그대로 추출해 검증한다. 게시 코드와 별도 예제 파일이 서로 달라지는 일을 피하기 위해 중복 사본은 관리하지 않는다.

검증 대상은 다음과 같다.

- 2편: 정상 정책 출력, 횟수·시간 초기화 순서를 바꾼 코드의 컴파일 실패
- 3편: 허용 범위의 양 끝과 일반 입력, 음수·0·상한 초과·숫자 외 문자·빈 입력, `static_assert` 실패
- 4편: 기본 목록, 빈 목록, 원소 하나, 검색 대상이 없는 목록

2026년 11월 19일 Linux의 GCC 14.2.0에서 검증했다. 기본 옵션은 `-std=c++20 -Wall -Wextra -Wpedantic -Wconversion -Werror`다. 2~3편의 완전한 예제는 C++11 모드에서도 컴파일해 본문에 적은 최소 버전을 확인했다.

컴파일과 실행 확인 31건이 모두 기대한 결과를 냈다. 여기에는 잘못된 타입 순서와 `static_assert`의 의도한 컴파일 실패도 포함된다. 4편은 빈 목록과 원소 하나, 검색 대상이 없는 경우까지 확인했다.

빌드는 `ASTRO_TELEMETRY_DISABLED=1 pnpm --config.verify-deps-before-run=false build`로 통과했다. 현재 설치된 의존성을 사용하고 환경의 사용자 홈 경로에 쓰지 않도록 실행 옵션을 지정했다. 생성된 HTML에서 새 글 5개, 내부 링크 151개, 게시된 코드 블록과 원문의 일치, 13부의 연속 회차 번호, 규칙 색인 512개를 확인했다. 브라우저에서의 시각 검토는 이번 검증 범위에 포함하지 않았다.

## 2부 예제 검증

2부는 5~19편이며 배정된 원문 항목 69개를 다룬다. 원문 파일의 blob SHA가 기존 계획과 같은 `b4065b4d7ecb11d6e13b4e3738344452ccccc252`임을 확인했다. 열거형 전방 선언과 평가 순서처럼 구분이 필요한 설명은 C++20 기준의 조건을 명시했다.

게시할 Markdown 코드 블록에서 프로그램을 추출해 Linux의 GCC 14.2.0으로 확인했다. 기본 옵션은 `-std=c++20 -Wall -Wextra -Wpedantic -Wconversion -Werror`이며, 열거형과 분기에는 `-Wswitch-enum`과 `-Wimplicit-fallthrough`를 추가했다. 본문에서 설명한 기능과 관련해 C++11·14·17 모드로도 해당 프로그램을 확인했다.

컴파일·실행 검사 97건이 통과했다. 범위 밖의 이름 사용, 축소 변환, const 객체 수정, 실행 중 값을 constexpr로 초기화하기, 잘못된 열거형 전달, 누락된 case, 암시적 fallthrough, 출력 불가능한 타입 전달은 의도한 컴파일 실패로 확인했다. 정의되지 않은 동작을 설명하는 조각은 실행하지 않았다.

13편은 최솟값·최댓값과 그 인접값, 음수·0·양수 11개를 서로 조합해 덧셈과 나눗셈 결과 242개를 확인했다. 기대값은 Python 정수 연산으로 구했고, C++ 프로그램에는 `-fsanitize=undefined -fno-sanitize-recover=all`을 적용했다. 이 242개 결과의 일치 검사는 위 97건 중 한 실행 검사에 포함된다.

전체 빌드는 경고 없이 통과했다. 생성된 연재 페이지 20개에서 내부 링크 866개, 코드 블록과 원문의 일치, 13부의 회차 번호, 규칙 색인 512개를 확인했다. 발행된 1~19편만 색인에서 연결하며, 20편 이후에는 글 주소를 만들지 않았다. 공식 문서 링크 20개의 앵커도 가져온 원문과 대조했다.

설치된 humanizer 스킬을 찾을 수 없어 저장소에 명시된 과장·반복·형식적 문장 축소 기준으로 직접 퇴고했다. 사실·예제·메타데이터를 보존했으며 실행 예제와 설명용 조각을 구분했다. 브라우저 시각 검토는 수행하지 않았다.

## 연재 전체의 범위

본편은 변수와 표현식, 함수와 인터페이스, 소유권, 클래스 생애, 상속, 오류 처리, 표준 라이브러리, 템플릿, 성능, 동시성, 파일 구성과 라이브러리 경계, 실제 도입까지 다룬다. 전체 13부 제목과 회차 범위는 `outline.csv` 및 사이트의 시리즈 안내 글에서 확인한다.

FAQ는 관련 회차에 배정하고 부록 C의 논의는 해당 주제에서 다룬다. 정규식·시간 등 원문이 미완성인 영역과 추가 자료, 용어와 참고문헌, 원문 변경 이력은 참고글 3개에 배정한다. 원문을 보충하는 설명은 원래의 권고나 표준의 보장처럼 서술하지 않는다.
